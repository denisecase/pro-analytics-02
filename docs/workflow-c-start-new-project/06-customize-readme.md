# 🟠 Customize README.md

> Review and customize README.md so it accurately describes your project.

## Previously

You should have chosen your problem and data,
created your custom GitHub repository, cloned it to your machine,
and opened the project in VS Code (`code .`).

## Step 1. Open README.md

In VS Code Explorer, open **README.md** in the repository root.

If the file does not exist, create it.

The README is the public landing page for your project on GitHub.
It should help others understand what the project does,
how to run it, and where to find additional information.

## Step 2. Review and Customize README.md

Your README should include:

- **Project Title** - the name of your custom project.
- **Author** - your name or alias.
- **Date** - year and month.
- **Overview** - one or two sentences describing your problem and data.
- **Commands** - instructions for setting up and running the project.
- **Links** - references to the original example, data, and other resources.

### Project Identity

Update the title, author, date, and description to reflect your project.

For example:

```markdown
# Project Title

Your Name or Alias
YYYY-MM

## Overview

One or two sentences describing your problem and data.
```

### Commands

Review the existing commands for setting up and running the project.

- Keep commands that are correct and useful.
- Update commands that refer to the original example or no longer apply.
- Add commands as you develop and verify your project.

Do not remove useful instructions simply because they were provided
in the original example.

### Links

Include links to:

- The original example project you are adapting.
- Your data source.
- Your project's `data-card.md`, if applicable.
- Other important project resources.

### Other Existing Content

Review any existing badges, images, descriptions, and documentation links.

- Keep content that remains accurate and relevant.
- Update project-specific names, URLs, and descriptions.
- Remove content that does not apply to your project.

**IMPORTANT:** Your README should describe YOUR project,
not simply repeat the original example.

See [Markdown Basics](https://denisecase.github.io/pro-analytics-02/reference/python/writing-readme/)
for help writing Markdown.

## Step 3. Preview

Open the Markdown preview in VS Code:

- Windows/Linux: `Ctrl + Shift + V`
- macOS: `Cmd + Shift + V`

Confirm the headings and links display as intended.

This is an initial version.
Continue updating README.md as the project develops.

Review it again when finalizing the project to ensure
the documentation accurately reflects the completed work.
