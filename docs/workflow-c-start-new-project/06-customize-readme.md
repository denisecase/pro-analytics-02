# 🟠 Customize README.md

> Review and customize README.md so it accurately describes your project.
> Use the required custom repository name if provided.

## Previously

You should have chosen your problem and data,
created your custom GitHub repository, cloned it to your machine,
and opened the project in VS Code (`code .`).

## Step 1. Open README.md

In VS Code Explorer, open **README.md** in the repository root.
If the file does not exist, create it.

The README is the public landing page for your project on GitHub.
It should help others understand what the project does,
how to run it, and where to find additional information.

## Step 2. Review and Customize README.md

README.md files general include the following with project-specific variations.

### Repo Title

One top-level heading with the repository name.

### Optional Badges

Badges are optional.
If you choose to keep them, check the links.
Project-specific links should use
**your GitHub account** and the **custom repository name**.

### Project Overview

Customize the author, date, and description to reflect your project.

### Developer Tools

Customize the developer tools to reflect the tools you choose to use.

### Links

Customize the links to use
**your GitHub account** and the **custom repository name**.

### Initial Customization

Review any existing badges, images, descriptions, and documentation links.

- Keep content that remains accurate and relevant.
- Update project-specific names, URLs, and descriptions.
- Remove content that does not apply to your project.

See [Markdown Basics](https://denisecase.github.io/pro-analytics-02/reference/python/writing-readme/)
for help writing Markdown.

## Step 3. Preview the Page

Open the Markdown preview in VS Code:

- Windows/Linux: `Ctrl + Shift + V`
- macOS: `Cmd + Shift + V`

Confirm the headings and links display as intended.

This is just the initial version.
Continue updating README.md as the project develops.

Finalizing the project includes ensuring
the README accurately reflects the completed work.

## Verification

- [ ] **README.md** exists in the project root.
- [ ] The README describes your custom project rather than the original example.
- [ ] Project-specific links use **your GitHub account**
- [ ] Project-specific links use **your custom repository name**.
- [ ] The Markdown preview displays correctly.
